## 0. 핵심 원칙

```
입력 게이트 → 숫자 수집 → 임차인 실체 → 시세 실측(호가 보정) → 이중 시나리오 → 보수 역산 입찰가 → 보고서 → 검수
```

**절대 규칙**:
1. **필수 입력이 비면 시작하지 않는다** — 옥션원 URL(또는 사건번호+법원) · 네이버 지도 URL. 급해도 생략 금지(범위를 줄인다). 취득 명의는 별도 언급 없으면 **법인** 으로 진행
2. **감정가 기준 사고 금지** — 모든 가치 판단은 `(월세×12) ÷ 요구수익률 + 보증금` 역산으로
3. **진술 임대료는 검증 대상** — 임차인/현황조사 월세는 반드시 인근 실측 시세와 대조, 시세 정합 월세를 기준선으로
4. **호가 ≠ 실거래** — 네이버 매물은 호가. 현장 중개사 청취가 없으면 보고서에 "호가 기준 초판" 표기
5. **숫자는 계산해서 넣는다** — 표·건수를 손으로 옮기지 않는다 (2026-09-14 수기 집계 오기 17↔18, 44↔46 실측)
6. **값을 지어내지 않는다** — 표본 부족·미확인은 공란 + 사유. 가정은 `report_tables.md` 가정 항목에 남긴다
7. **세금·법률은 원문으로** — 법제처 OpenAPI 조문 원문 확인 후 판단, 최종은 세무사 컨펌
8. **네이버 카드만으로 시세를 확정하지 않는다** — 비교군으로 쓸 매물은 **상세를 열어 확인**한다. 카드의 면적란은 중개사가 호실 전체 면적을 적고 **구분임대 한 칸 월세**를 붙이는 일이 있다 (2026-10-02 광진두산위브파크 실측: 카드 "전용 161.96㎡ 월 130만" → 상세 "실평수 약 10평·단독공유주방". 이 오독으로 기준선을 월 125만으로 잡아 1판 결론이 뒤집혔다. 정정 후 210만)

## 2. 파이프라인 (8단계)

### STEP 0. 입력 게이트 — 누락 정보 질문 ★필수

1. `case_template.yaml` → 보고서 폴더 `case.yaml` 복사, 요청에서 알 수 있는 값 채움
2. 검사:
   ```bash
   cd scripts/auction && python -m bid_report.build_report <case.yaml> --check   # exit 2 = 필수 누락
   ```
3. **첫 응답에 질문을 한 번에** 보낸다. 필수 2종이 다 있으면 묻지 않고 바로 시작한다 — 권장 항목은 아래 기본값으로 진행하고 보고서에 '가정'으로 표기

| 구분 | 항목 | 비었을 때 |
|---|---|---|
| **필수** | 옥션원 URL(product_id) — 없으면 **사건번호 + 관할법원** | 시작 금지. 사건번호는 법원마다 겹친다 |
| **필수** | 네이버부동산 지도 URL (거래유형·물건종류·층 필터 적용) | 시작 금지. 필터가 비교군을 결정 |
| 권장 | 취득 명의 (법인/개인) + 법인이면 설립연수·본점 | **법인(설립 5년 이내 가정)** 으로 가정. 과밀억제권역이면 9.4%, 아니면 4.6% — 원문 확인 후 표기 |
| 권장 | 중개사 청취 성사가 | "호가 기준 초판" 표기 |
| 권장 | 임차인 사업자번호/정확한 상호 | 상호명 검색으로 대체 |
| 권장 | 현장 임장 (층별 안내판·공실·관리비·영업) | "미실시" 표기 |
| 권장 | 대출 조건 (LTV·금리) | min(감정70%, 낙찰80%) · 5.5% |
| 권장 | 요구수익률 기준 | **6%** + 5.5~6.5% 민감도 (2026-10-22 7.5% → 6% 변경. 민감도는 기준 ±0.5%p 자동) |

**시간 압박 시**: 게이트는 유지하고 **범위를 줄인다** — 06 임차인·09 수요 슬라이드, 사진 발췌 수를 줄인다. **지도 콜아웃(08)·시나리오 계산·가정 표기는 줄이지 않는다.**

> 실측(2026-09-14 스킬 없는 베이스라인): "내일 입찰, 급해" 요청에 에이전트는 법원·마감시각만 묻고 네이버 URL·명의를 묻지 않았으며, 지도 매핑 슬라이드를 임의로 생략했다.

### STEP 1. 물건 확보 · 옥션원 수집

```bash
cd scripts/auction
python -m bid_report.fetch_case <product_id> "<보고서폴더>"   # exit 3 = 사진 일부 누락
```

- 산출: `raw/detail.*` · `raw/auction_full.png` · `images/auc_p1.png`(개요~임차인) · `images/auc_p2.png`(건축물~매각사례) · `images/{번호}_{라벨}.jpg`
- `raw/fetch_summary.json` 의 `photos_found == photos_saved` 확인, 위도·경도 확인
- 신규 발굴이면 먼저 `auction1_search.py` → `auction1_screen.py --xlsx <파일>` (최신 파일 자동선택은 가나다 정렬이라 `--xlsx` 명시)

### STEP 2. 물건 분석 — 부가남 체크리스트

`raw/detail.txt` 를 읽고 `분석체크리스트.md` 순서대로:

1. **가격 검산**: 진술 월세 기준 최저가 수익률 → 이후 시세 정합 월세로 재계산
2. **권리**: 말소기준 · 인수권리 · 압류(당해세는 배당 순위 문제) · 채권액 vs 최저가(취하 유인)
3. **임차인 구조**: 대항력(사업자등록 vs 말소기준) · 배당요구 여부(없으면 보증금 전액 손실 → 명도 협상 변수) · 환산보증금
4. **특수**: 물건번호 복수(배당기일·인도명령 지연) · 가벽 없는 통물건(대출) · 폐문부재 · 관리비
5. **유찰 횟수의 의미**: 3회↑면 감정가와 시장 괴리 — 이유를 특정
6. **현황사진 전량 Read**: 내부(인테리어 투자=잔류 유인 / 빈 좌석=감액 명분) · 외관(가시성·옆 필지 공사) · 배치도(트인 구조=재임대 용이)

### STEP 3. 임차인 실체 조사 (권장 — 시간 없으면 초판에서 생략 가능)

| 조사 | 방법 | 판단 |
|---|---|---|
| 사업자·상태 | `bizno.net/article/{사업자번호}` (curl 가능) | 계속/휴·폐업, 본점 주소 = 본건 여부 |
| 재무 3개년 | 잡코리아 기업정보 "재무현황 전체보기" (NICE 제공, 천원) | 매출 추세 · 영업이익 · 부채비율 · 유동비율 · 연 임대료 ÷ 영업이익 |
| 인원 추이 | `allthatcompany.com` (국민연금 월별) · NICE BizINFO(최신월) | 입주 시점 대비 인원 → 1인당 면적 → 공간 과잉 여부 |
| 평판 | 잡플래닛 검색 JSON(`rate_total_avg`) · 웹검색(소송·제재) | 이직·조직 리스크 |
| 특수관계 | 법인등기부(인터넷등기소) 임원 vs 소유자 | 봉담 건: 소유자=임차법인 사내이사 → 결론 변경 |

**결론 형식**: "그대로 잔류" 시나리오는 대항력 없는 한 존재하지 않는다 → **감액 재계약 월세 추정** + 남을/나갈 이유 표.

### STEP 4. 시세 실측 — 네이버부동산 (naver-land SOP)

1. `네이버부동산_매물조사_SOP.md` STEP 1~4 (headed 전환 게이트 필수)
2. **URL 거래유형이 섞였어도**(`B2-A1`) 카드 파싱은 `parse_listings.parse_card` 하나로 처리 — `bid_report.comps` 가 사용
3. 수집물: `scrape.js` → `raw/naver_raw.json` · `scrape_markers.js` → `raw/naver_markers.json` · 패널 닫은 지도 캡처 → `images/map_crop.png`(크롭 좌상단을 case.yaml `map.crop_offset` 에 기록)
4. 게이트: `__meta.count` = 화면 "매물 N" · `markers failed` 개수 기록(보고서 각주에 미매핑 명시)
5. **매매 0건일 수 있다** → 요구수익률 역산 불가 → 가정값 + 민감도 (보고서에 명시)
6. ★ **비교군 매물 상세 전수 확인 (필수)** — 아래 STEP 4-1
7. **본건 적용 시세**: 본건과 같은 체급(층·면적) 비교군 중앙 → 신축·역세권 가산 → "시세 정합 월세" (현 임차조건과 괴리율 명시)
   - 비교군 기준은 물건마다 다르다 → `case.yaml` `comps: {min_py, floor, exclude_contains}` 로 지정 (기본 60평·층 무관)
8. **매매 실거래** (호가 0건이거나 분할·출구 검토 시): `POST https://rt.molit.go.kr/pt/gis/ptDtl.do` · `srhThingSecd=F` · `srhDelngSecd=1` · `srhAprpnHsmpCode=법정동10자리` (나머지 dtl* 공란 = 전 기간) → `danjiList` → `raw/rtms_*.json`
   - 법정동코드는 입지등급 캐시(`%LOCALAPPDATA%\auction1\locale_cache`)의 `ldongCd`에서 확인
   - 필터: `regstrCd=집합` · `dspsSecd≠Y`(해제 제외) · 용도 업무/근생(**숙박 분양호텔 소형이 섞여 단가를 왜곡**) · 층 · 최근 3년
   - 법인→공공기관 **일괄 직거래**는 시장가로 쓰지 않는다 · 통건물 매각 일부 호실도 제외
   - ⚠️ 공공데이터포털 `RTMSDataSvcNrgTrade` 는 현재 키로 403 (활용신청 안 됨)

**분할 임대 검토 (선택, 대형 통임대 물건)** — `case.yaml split` 에 정의하면 12-A 슬라이드 생성
- 월세: `comps.size_bands` 로 면적대별 평당(1층 제외) + **목표 면적대 경쟁 매물 수**

- 원칙: **확인 안 된 분할 프리미엄은 입찰가에 넣지 않는다** — 명도 후 옵션

### STEP 4-1. 매물 상세 전수 확인 ★필수

카드 텍스트는 요약이고, **가격의 의미는 상세에만 적혀 있다.**

```bash
# 1) 카드에서 상세 링크(articleNo) 수집 — 클릭보다 안정적
$B js "JSON.stringify([...document.querySelectorAll('li[class*=ArticleCard]')]
  .filter(li=>/(매매|월세)/.test(li.textContent||''))
  .map(li=>({href:li.querySelector('a')?.getAttribute('href'),
             head:(li.textContent||'').replace(/\s+/g,' ').slice(0,70)})))"

# 2) 상세 순회 — ⚠️ 네이버 로그인 필요 (미로그인 시 nid.naver.com 으로 리다이렉트)
for id in <articleNo들>; do
  $B goto "https://fin.land.naver.com/articles/$id"; sleep 2
  $B js "document.body.innerText" > raw/detail_$id.txt
done
```

- **로그인**: `$B handoff "네이버 로그인해 주세요"` → 사용자 로그인 → `$B resume`. 로그인 후 지도 위치·필터가 초기화되므로 **원래 URL 로 다시 goto** 한다
- 저장: `raw/naver_basement_details.json` 등 (`창닫기` ~ `건축물 정보` 구간만 추출하면 본문·기본정보가 깔끔히 남는다)

**상세에서 반드시 읽을 것**

| 항목 | 왜 |
|---|---|
| **매물 소개 본문** | "실평수 약 10평", "점포6개 총 월790만", "공유주방 6실 구분임대" — **면적·가격의 진짜 단위** |
| **현재업종 / 추천업종** | 공실(빈점포) 여부 · 수요 업종 특정 |
| **관리비** | 체납관리비 인수 추정의 분모 (호실당 관리비 × 실수 = 월 관리비) |
| **권리금 / 융자금** | 무권리·렌트프리는 공실 유인책 = 수요 약세 신호 |
| **입주가능일** | 즉시입주 = 공실 |

**모순 탐지 체크 (이게 조기 경보다)**
- 면적이 7배 차이나는 두 매물이 **같은 월세** → 하나는 구분임대 한 칸이다
- 매매 호가 ÷ 월세 수익률이 1~2%로 비현실적 → **월세 쪽이 한 칸 가격**일 가능성
- 상세의 "실평수"와 카드 "전용면적"이 다르면 **상세를 믿는다**

**구분임대(공유주방·구분점포) 물건의 원칙**
- 실제 수익 = 한 칸 가격 × 실수 (예: 보증 900/월 130 × 6실 = 보증 5,400만 / 월 780만)
- **통임대 시세와 섞지 않는다.** 비교군에서 빼려면 `comps.exclude_contains`
- 본건이 설비 없는 상태면 **입찰가는 통임대 기준으로만** 잡고, 전환은 명도 후 옵션으로 둔다 (전환비·기존 운영자와의 경쟁을 가격에 넣지 않는다)

## 5. 경쟁 낙찰가 예측 — 2025타경1684 실패에서 만든 규칙

> **2026-09-29 봉담 DS타워 7층**: 예측 11.3~12.4억(입찰 1.7명) → 실제 **낙찰 17.25억 · 입찰 7명 · 차순위 15.18억**.
> 최저가 대비 배율 예측 1.108 vs 실제 **1.603**. 제시한 "90% 승률 13.29억"은 실제 승률 0%.

### 5-1. 절대 하지 말 것

| 금지 | 이유 |
|---|---|
| **준공연도·면적대가 다른 인근매각 표본으로 회귀** | 봉담 사례: 대형 표본이 2015년 구축 1건뿐인데 2023년 신축에 적용. 신축 프리미엄을 0으로 깐 셈 |
| **표본 15건 미만에서 회귀선·예측구간 제시** | 정밀해 보이는 숫자가 판단을 지배한다. 표본 부족이면 "표본 없음 · 밴드만 제시"로 쓴다 |
| **"직전 회차 유찰 = 시장이 그 가격을 거부"로 해석** | 봉담 차순위 15.18억 = **2차 최저가 15.372억의 98.7%**. 유찰은 거부가 아니라 아슬아슬하게 빗나간 것일 수 있다 |
| **밸류에이션용 할인 임대료를 경쟁가 예측에 그대로 사용** | 특수관계라 월1,400→1,150으로 깎은 건 내 밸류에이션엔 맞지만, **시장은 명목 임대료로 계산한다** |
| **네이버 호가를 경쟁가 예측에서 배제** | 실거래 추정엔 호가를 할인해야 하지만, **입찰자들이 보는 화면은 호가다.** 경쟁가 예측에는 호가가 더 나은 지표 |

### 5-2. 표준 절차

1. **경쟁가와 내 상한을 분리해 두 번 계산한다.**
   - 내 상한 = 보수 가정(현장 성사 임대료 · 실거래 평단가)
   - **경쟁가 = 낙관 가정(등재 임대차 명목 임대료 · 네이버 호가 평단가)**
   - 두 값의 간극이 곧 "내가 질 확률"이다. 간극이 크면 **입찰 포기를 먼저 검토**한다
2. **내재 캡레이트로 역산한다.** 명목 임대료 기준 시장 캡레이트(네이버 매매×월세 매칭)를 구하고, 그 캡을 본건에 대입한 값이 **경쟁가 상단**이다.
   - 봉담: 시장 호가 캡 4.4~6.6% · 낙찰가 내재 캡(월1,400) **10.03%** · 차순위 11.45% → 시장 캡보다 여전히 훨씬 높았다. 즉 17.25억도 "싼 물건"이었다
3. **채권최고액을 경쟁가 상단 후보로 반드시 올린다.** (§5-3)
4. **입찰인원은 유효조회로 추정하고, 회귀로 추정하지 않는다.** 봉담: 유효조회 2주 45건 → 실제 7명(**약 16%**). 면적 회귀 예측 1.7명은 완전히 빗나감
   - **보고서에 "예상 입찰인원 = 조회 × 10~20%"를 숫자로 쓴다.** 조회수만 적어 두고 환산을 빼먹지 않는다
   - **지역 평균 입찰인원(옥션원 동별 1년 통계)은 인용하지 않는다.** 구축·장기유찰 물건이 섞여 쓸모없다 (운양: 평균 2.06명 인용 → 실제 16·19명)
5. **경쟁 강도 3요인을 체크한다.** (§5-4)

### 5-4. 경쟁 강도 3요인 (2026-10-15 신설 — 작성자 가설, 3건 관찰·검증 중)

> **2026-10-15 운양프라자 8층(2025타경5020)**: 상한 (1) 3.81억 · (2) 1.90억 → 실제 낙찰 **(1) 4.46억 16명 · (2) 2.215억 19명**. 둘 다 상한 대비 +17%, 최저가 대비 +18~24%. 2주 조회 148·97건 대비 입찰 11%·20%.

| 요인 | 쉬움 (경쟁↑) | 어려움 (경쟁↓) |
|---|---|---|
| ① 권리분석 난이도 | 인수권리 없음 · 대항력 임차인 없음 | 유치권·법정지상권·대항력 임차인·지분 |
| ② 경락대출 용이성 | 감정 70%·낙찰 80% 무난 | 대출 제한(특수용도·지분·위반건축물 등) |
| ③ 낙찰 금액대 | 소액(약 5억 이하) — 대중 입찰자 유입 | 10억 이상 — 자기자금 부담으로 인원 감소 |

| 물건 | 낙찰가 | 입찰 | 3요인 | 최저가 대비 |
|---|---:|---:|---|---:|
| 운양 807호 | 2.2억 | 19명 | 쉬움·쉬움·소액 | 1.24배 |
| 운양 801·802호 | 4.5억 | 16명 | 쉬움·쉬움·소액 | 1.18배 |
| 봉담 DS타워 7층 | 17.25억 | 7명 | 쉬움·쉬움·고액 | **1.60배** |


적용 규칙:
1. **3요인이 모두 쉬움 + 소액이면 예상 입찰인원은 조회 × 20%(상단)** 로 잡고, 경쟁가 밴드 하단을 "최저가 × 1.15" 이상으로 둔다.
2. **10억 이상은 인원을 적게 잡되, 경쟁가 상단을 최저가 × 1.5배 이상까지 따로 계산한다.** 인원이 적어도 자금 있는 소수 중 한 명이 높게 쓰면 끝난다(봉담 7명·1.60배). **인원 감소 ≠ 낙찰가율 하락.**
3. 내 상한이 "최저가 × 1.15"보다 낮으면 **입찰 포기 또는 다음 회차 대기를 먼저 검토**한다.
4. 표본 3건짜리 가설이다. 결과가 나올 때마다 위 표에 한 줄씩 추가하고, 10건이 쌓이면 규칙을 재검토한다.

### 5-3. NPL·채권자 유입 체크 (신설 — 필수)

경매개시 채권자가 **유동화전문회사·대부업 법인**이면 아래를 보고서에 명시한다.

| 항목 | 확인 |
|---|---|
| 1순위 채권최고액 | 예상배당표에서 확인 |
| **낙찰가가 채권최고액을 넘는 구간** | 채권자(또는 채권 양수인)가 유입 시 **상계신청**으로 실현금 부담 = 낙찰가 − 배당액. 채권최고액 근처까지는 사실상 공짜로 올려 쓸 수 있다 |
| 근저당권이전 부기등기 | 경매 진행 중 개인·대부법인으로 **론세일**됐는지 |
| 결론 | **"경쟁가 상단 = max(시장 캡 역산가, 1순위 채권최고액 + 경매비용)"** 으로 잡는다 |

> 봉담 실제: 채권최고액 16.935억 · 낙찰 **17.2511억** (초과분 3,161만 ≈ 경매비용). 내가 §5-3을 갖고 있었다면 경쟁가 상단을 17억대로 잡았을 것이다.

| 단지 필지 안의 단지내상가 | 붉은 외곽선으로 따로 그리지 않고 단지 외곽선에 포함 → **상업 필지 수가 수요 슬라이드의 상가필지 수보다 적게 나온다**(운양 21 → 16). 차이를 각주에 적는다 |
| 업소 좌표가 옆 필지로 떨어진다 | 그 블록 일부가 외곽선에서 빠진다 — 개수와 위치를 각주에 적는다 |
| 800m 경계 바로 밖 단지 | 집계 대상이 아니므로 그리지 않는다 (임의로 추가하면 수요 슬라이드와 숫자가 어긋난다) |
| 슬라이드에서 라벨이 안 읽힌다 | 1937px 이미지를 550px 로 줄이면 21px 글자가 6px 이 된다 → **슬라이드판은 번호 배지 + 옆 표**로 분리 |

**원칙** — 이 지도는 **집계 범위를 보여주는 그림**이지 주동선을 증명하는 자료가 아니다. 단지 정문 위치·횡단보도·실제 보행 흐름은 임장으로 확인하고, 지도만으로 "주동선 핵심"이라고 쓰지 않는다.
